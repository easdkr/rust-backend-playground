# rust-backend-playground — frontend

TanStack Start + React 19 + Vite 8 client for the Rust/Axum backend
(`http://127.0.0.1:3000` by default; the Vite dev server runs on `3001` to
avoid the conflict).

## Quick start

```bash
cp .env.example .env       # set RUST_API_BASE_URL=http://127.0.0.1:3000
bun install
bun run dev                # http://localhost:3001
bun run typecheck          # tsc --noEmit, must exit 0
```

## Why loaders call server functions

Loaders in TanStack Router are **isomorphic** — the same code path runs on
the server during SSR and on the client during navigation. That means any
import that resolves to a route component or loader gets bundled into the
browser, including anything those modules transitively reach. If a loader
called `fetch(`${process.env.RUST_API_BASE_URL}/posts`)` directly, the
browser bundle would either contain the backend URL (with a `VITE_*` env
var) or get an undefined base URL (without one), and the access token
would have to be reachable from the client to attach an
`Authorization` header. We proxy every backend call through a
`createServerFn` from `@tanstack/react-start` instead. The server function
runs server-side, has access to `process.env.RUST_API_BASE_URL`, holds the
in-memory access token (`src/lib/api/auth-store.ts`), and only the JSON
response is shipped to the browser. The frontend thus never needs to know
the backend URL or the JWT — both stay in the Node process that the TanStack
Start dev server boots.

## Layout

```
src/
  routes/                 # TanStack Router file routes (isomorphic)
  router.tsx              # createRouter(...) for the app
  routeTree.gen.ts        # AUTO-GENERATED by the TanStack Start vite plugin
  lib/
    api/
      config.ts           # process.env.RUST_API_BASE_URL → ApiConfigError
      auth-store.ts       # in-memory access token (server-side only)
      client.ts           # apiFetch<T>(path, init) wrapper
      errors.ts           # ApiError, ApiConfigError, UnauthorizedError
      index.ts            # barrel export
```

## Environment

| Variable | Required by | Where it's read | Client-visible? |
|---|---|---|---|
| `RUST_API_BASE_URL` | `src/lib/api/config.ts` (server-side) | server process | **No** — do NOT prefix with `VITE_` |

`.env.example` documents the only required variable. `RUST_API_BASE_URL`
must point at the running Rust backend; the default is
`http://127.0.0.1:3000` to match `crates/server/src/main.rs`.
